# FTC 24135 · BioBuzz: Codebase Guide

A plain-language map of **everything** in this repo. Read it top to bottom and you'll know what each file is, how the pieces connect, and where your code goes.

> **TL;DR:** This is the official **FTC SDK v12.0** (FIRST Tech Challenge, **BIOBUZZ 2026–2027** season), unchanged. It builds **one Android app** (the *Robot Controller*) that runs on the robot's Control Hub. **No team code has been written yet.** `TeamCode/` is empty and is where ours will go. Everything else is FIRST's framework plus 65 example programs you can copy.

---

## 1. The 60-second mental model

```
 Driver Station (Android phone/tablet + gamepads)
        │  Wi-Fi
        ▼
 Robot Controller app  ◄── THIS REPO builds this APK
 (runs on the REV Control Hub)
        │  USB / RS-485 / I2C
        ▼
 Motors, servos, sensors, cameras
```

- **OpMode** = one robot program. The drivers pick it from a menu on the Driver Station and press INIT, then START.
  - **TeleOp**: humans drive with gamepads.
  - **Autonomous**: the robot runs on its own (first 30 s of a match).
  - **Utility** (new in 11.2): tools that show up in a separate Utility menu.
- Code reaches hardware **by name**. The names come from a *robot configuration* you set up on the Driver Station, e.g. `hardwareMap.get(DcMotor.class, "left_drive")`.
- `telemetry` sends text back to the Driver Station screen. `gamepad1`/`gamepad2` give you joystick and button state.
- The actual robot libraries (motors, vision, the web IDE, and so on) are **not in this repo**. They're downloaded as Maven packages (see §3). This repo is just the app shell, the samples, and an empty slot for our code.

### Two OpMode styles (every sample uses one)
| Style | Base class | How it works |
|---|---|---|
| **Linear** | `LinearOpMode` | You write `runOpMode()`: init code, `waitForStart()`, then a `while (opModeIsActive())` loop. Reads top-down. Best for autonomous. |
| **Iterative** | `OpMode` | The SDK calls `init()`, `init_loop()`, `start()`, `loop()` (repeatedly), `stop()`. Best for TeleOp state machines. |

### Annotations that register an OpMode
```java
@TeleOp(name = "Shows on DS menu", group = "Sorting group")   // or @Autonomous / @Utility
@Disabled                                                      // hides it; delete this line to show it
public class MyOpMode extends LinearOpMode { ... }
```
The SDK finds annotated classes automatically, so there's no list to maintain.

## 3. How the build fits together

| File | What it does |
|---|---|
| `settings.gradle` | Includes both modules. Uses the plugin repos `google()`, `mavenCentral()`, `gradlePluginPortal()`. |
| `build.gradle` | Declares `com.android.application` / `com.android.library` **8.13.2** (needs Android Studio *Narwhal 3 Feature Drop* or newer). |
| `build.common.gradle` | `compileSdk 30`, `minSdk 24`, `targetSdk 28`, Java 8, NDK 21.3, ABIs `armeabi-v7a` + `arm64-v8a`, `applicationId com.qualcomm.ftcrobotcontroller`. **Reads `versionCode`/`versionName` out of FtcRobotController's manifest** with a regex, so the app version always matches the SDK version. Signing: a release build uses the `APK_SIGNING_*` env vars if set, otherwise the debug keystore in `libs/`. |
| `build.dependencies.gradle` | Pulls in the real SDK from Maven, `org.firstinspires.ftc:*:12.0.0`: **RobotCore** (OpMode, hardware interfaces), **Hardware** (device drivers), **FtcCommon** (the robot service, UI helpers), **RobotServer** (the on-robot web server), **OnBotJava** and **Blocks** (the in-browser editors), **Vision** (VisionPortal, AprilTag, color processing), **Inspection** (self-inspect). |
| `FtcRobotController/build.gradle` | Android *library*. Adds `BuildConfig.APP_BUILD_TIME` (a build timestamp). |
| `TeamCode/build.gradle` | Android *application* (namespace `org.firstinspires.ftc.teamcode`). `implementation project(':FtcRobotController')`, legacy JNI packaging. **If you need custom Gradle config or extra libraries, put them here.** |

**Build and deploy:** open the folder in Android Studio, plug in or connect to the Control Hub, pick the **TeamCode** run config, and press ▶. From the CLI, `./gradlew :TeamCode:assembleDebug` produces `TeamCode/build/outputs/apk/debug/`.

## 4. The app shell: `FtcRobotController/.../internal/`

| File | Role |
|---|---|
| `PermissionValidatorWrapper.java` | **The launcher activity.** Asks for storage, camera, location, and phone-state permissions (with a user-facing explanation for each), then opens the main activity. |
| `FtcRobotControllerActivity.java` | **The main screen (~845 lines).** Binds to `FtcRobotControllerService` (where the robot event loop runs), holds a Wi-Fi lock, shows status (device name, network, robot state, gamepads, active OpMode, errors), and handles the overflow menu (Settings, Restart Robot, Configure Robot, Program & Manage, About, Exit). It also hands USB-attach events to the event loop, starts the OnBot Java/Blocks web server, dims the screen when idle, and restarts the robot when the configuration changes. |
| `FtcOpModeRegister.java` | A hook for *manually* registering OpModes. Empty, because annotations handle registration. |

**`AndroidManifest.xml`** also declares `FtcRobotControllerService` (the robot runtime) and `RunOnBoot` (auto-starts the app when the Control Hub powers on).

**`res/`**: `layout/activity_ftc_controller.xml` (the main screen), `menu/ftc_robot_controller.xml` (the overflow menu), `values/strings.xml|styles.xml|dimens.xml`, `xml/app_settings.xml` (settings screen), `xml/device_filter.xml` (which USB devices wake the app), `raw/gold.wav` + `raw/silver.wav` (sounds used by the sound samples), and the icons.

## 5. Every sample OpMode: `external/samples/`

All samples are **`@Disabled`**. To use one, copy it into `TeamCode/.../teamcode/`, rename it, and delete `@Disabled`. **The quoted names are the device names your robot configuration must use** (or change them in the code).

**Naming convention** (from `sample_conventions.md`):
`Basic*` = minimal skeleton · `Robot*` = full drivable example · `Concept*` = one idea demonstrated · `Sensor*` = read one sensor · `Utility*` = tool.
Patterns: `Sensor‑Company‑Type`, `Robot‑Mode‑Action‑OpModeType`, `Concept‑Topic‑OpModeType`.

## 6. Built-in utilities: `external/utilities/`
These two are **not disabled** and use the `@Utility` annotation, so they **appear on the Driver Station's Utility menu as soon as the app is installed.**

| File | What it does |
|---|---|
| `UtilityTestGamepad` | Live readout of both gamepads: sticks, triggers, every button, PS4 touchpad. Use it to check that the controllers work. |
| `UtilityTestHardware` | Finds **every device in the active configuration** (skipping the hubs themselves). D-pad left/right selects a device, then you can run that motor/servo/CR servo or read that sensor/IMU/camera, one at a time. Use it to separate wiring problems from code problems. ⚠️ It drives one actuator at a time; be careful with mechanically linked motors. |

## 7. What's special about this version (v12.0, BIOBUZZ)
- **Breaking:** AprilTag detections can now be **clusters** (groups of tags sharing one origin). Code must check `instanceof AprilTagSingleDetection` vs `AprilTagClusterDetection` and cast. All samples already do this.
- `getCurrentGameTagLibrary()` returns the BIOBUZZ tags. Each cluster's origin is the center of the Cell opening, which makes it a convenient aiming target. **BIOBUZZ tags move, so don't use them for field localization.**
- The robot configuration editor has a tree view. The DS shows gamepad indicators in orange when a gamepad is on the generic Android driver.
- Since 11.2: Gradle 9.1 + AGP 8.13.2, the `@Utility` OpMode type, the Test Hardware/Gamepad utilities, `PwmControl.setPulseWidth()`, and UVC camera quirks.
- The full history is in `README.md` → *Release Information*.

## 9. How to start writing our robot code
1. Configure the robot on the Driver Station (name every motor, servo, and sensor).
2. Run **Utility → Test Hardware** to confirm each device works.
3. Copy `externalhardware/RobotHardware.java` + `ConceptExternalHardwareClass.java` (or a `Robot*` sample) into `TeamCode/src/main/java/org/firstinspires/ftc/teamcode/`.
4. Rename the classes, change the `@TeleOp`/`@Autonomous` names, delete `@Disabled`, and match the hardware names to your configuration.
5. Press ▶ in Android Studio with the **TeamCode** config selected. The OpMode appears on the DS menu.

**Rules of thumb**
- Only edit files in `TeamCode/`. Leave `FtcRobotController/` and the root Gradle files alone, so SDK upgrades merge cleanly (upgrade by pulling the next release from `FIRST-Tech-Challenge/FtcRobotController`).
- Mismatched hardware names are the #1 crash cause (`"Unable to find a hardware device with name …"`).
- In a linear loop, always check `opModeIsActive()`, or the Stop button won't work.
